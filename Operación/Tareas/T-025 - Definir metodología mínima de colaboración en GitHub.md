# Definir metodología mínima de colaboración en GitHub

Acordar una forma sencilla y compartida de trabajar en GitHub antes de que el desarrollo de ACE aumente la cantidad de cambios simultáneos.

## Incluye

- Cuándo trabajar directamente y cuándo abrir una rama.
- Convención mínima para nombrar ramas.
- Cuándo corresponde crear un pull request.
- Quién revisa, corrige y decide el merge.
- Cómo mantener una rama actualizada y resolver cambios concurrentes.
- Relación entre las tareas del repositorio, los commits y GitHub.

## Fuera de alcance inicial

- Automatizaciones, bots o flujos complejos.
- Una estrategia con múltiples ramas permanentes sin necesidad demostrada.
- CI/CD y reglas técnicas propias de la futura implementación del producto.

## Criterio de aceptación

- Existe una convención breve que los tres integrantes pueden aplicar sin capacitación extensa.
- La metodología protege `main` sin convertir cada cambio pequeño en burocracia.
- Las responsabilidades de autor, revisor y responsable del merge son claras.
- La propuesta se prueba con un caso real antes de considerarse definitiva.

## Activación

Esta tarea pertenece al backlog transversal. Se asignará a un módulo vigente cuando el equipo decida ejecutarla.
